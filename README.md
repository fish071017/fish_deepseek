# 像素街机 PIXEL ARCADE

四款像素风手机小游戏，单文件零依赖。竖屏、单手、短单局，难度不友好。

## 怎么玩

**手机上（推荐）**

```powershell
# 在 pixel-arcade 目录下起一个本地服务
node _check\server.js
# 然后手机浏览器打开 http://<你电脑的局域网IP>:8123/
```

或者把整个 `pixel-arcade` 文件夹丢到任意静态托管（GitHub Pages / Vercel / Netlify / 对象存储），
手机访问 URL 后会提示「添加到主屏幕」——装完就是全屏 App，断网也能玩。

**电脑上**：直接双击 `index.html` 即可。

## 四款游戏

| 游戏 | 玩法 | 上头点 |
|---|---|---|
| **像素试管** | 把同色方块倒进同一个瓶子，每关只能撤销 1 步 | 反向生成保证一定有解，但只有 1 根空管 |
| **箭头开路** | 点亮路径通畅的箭头（一次只消一个），限时内清空整盘 | 4×4 起手一路长到 8×8 近 50 个箭头 |
| **一指点色** | 四条轨道方块涌来，点掉最下面那个，同色连击加分 | 速度随时间指数上涨，几十秒一局 |
| **像素跳跃** | 按住蓄力、松手起跳，落在平台正中间加倍 | 平台越来越窄还会左右飘 |

## 设计取舍

难度按「折磨优先」调（参考《羊了个羊》路线），但**绝不做不可解的关卡**：

- **试管**：从「已通关」状态反向打乱，每一步都是合法操作，所以正着走一定能解回去。
- **箭头**：反向放置生成——每个箭头落位时它的路径必然是空的，
  因此按落位逆序点就一定能清空。规则上「点一个只消一个」，
  保证不会因为一次点击引发不可控的全盘雪崩（这个坑踩过，见下）。

## 已验证项

`node _check/verify.js` 会跑完整验证（直接加载 `index.html` 的真实实现，不是副本）：

- 试管 1–14 关各 60 局：贪心求解 **100% 可解**
- 箭头 1–14 关各 30 局：随机顺序 **100% 可清空，零死局**
- 过关续关、结算面板、存档写入、分享文案

当前结果：全部通过。

## 文件

```
index.html              全部代码（HTML/CSS/JS 单文件，约 70 KB）
manifest.webmanifest    PWA 清单
sw.js                   Service Worker（离线缓存）
icon-192.png            图标
icon-512.png            图标
_check/verify.js        关卡逻辑与流程验证
_check/server.js        本地静态服务器（手机真机测试用）
_check/gen-icon.js      程序化生成图标（改配色后重跑即可）
```

URL 支持 hash 直达，方便分享和调试：

- `index.html#home` — 游戏列表
- `index.html#game/arrow` — 直接进箭头开路
- `index.html#game/arrow/6` — 从第 6 关开始

## 踩过的坑（备查）

1. **箭头玩法第一版是错的**：原设计「点一个箭头，撞飞路径上所有箭头」，
   量化后发现**一次点击就能清空整个盘面**（最优点击数恒为 1）——
   因为反向生成倾向于把箭头放在靠边的位置，一撞就雪崩。
   换成「被挡住就点不动、一次只消一个 + 限时」后，起手可选 4–6 个、
   全盘 48 个箭头，搜索压力才真正建立起来。

2. **固定逻辑分辨率会被裁**：最初写死 360×640 并按 cover 缩放，
   在 19.5:9 的手机上左右两侧被切掉，静音键和最高分都看不见。
   改成**宽度固定、高度按设备宽高比推算**，全宽永远完整可见。

3. **不要用 `window.innerWidth` 定画布尺寸**：某些环境下它与真实视口不一致
   （本机无头 Edge 就报 492 而实际视口 390），会导致画布溢出被裁。
   改用 `canvas.clientWidth` + CSS `100dvh`。

4. **顶栏文字会重叠**：游戏名居中 + 右侧状态读数在窄屏上必然撞车。
   改成左中右水平分区。
